# 창업 입지 폐업 위험 예측 서비스: 기획서와 개발 현황

작성일: 2026년 11월 16일

이 문서는 세 부분으로 되어 있습니다. 1부는 기획, 2부는 지금까지 개발한 것, 3부는 앞으로 개발할 것입니다.

현재 상태를 한 줄로 요약하면, 데이터 정제와 예측 모델, 데모 지도까지 끝났고 실제 서비스(FastAPI 서버와 카카오맵 화면) 개발이 남았습니다.

---

## 1부. 기획

### 1.1 서비스 개요

예비 창업자가 업태와 면적을 고르면, 서울과 경기도에서 3년 안에 폐업할 위험이 낮은 동네를 지도에 보여주는 서비스입니다. 특정 위치를 누르면 그 자리의 위험 수치와 이유를 알려줍니다.

LLM을 쓰지 않고, 공공데이터로 직접 학습한 머신러닝 모델이 핵심입니다.

| 항목 | 내용 |
| --- | --- |
| 예측 대상 | 개업 후 3년 내 폐업 여부 |
| 지역 | 서울특별시, 경기도 |
| 업종 | 일반음식점 (카페 등 휴게음식점은 추후 추가) |
| 입력 | 업태, 점포 면적, 지역 또는 지도 위 위치 |
| 출력 | 구역별 폐업 위험 지도, 위험이 낮은 구역 추천, 위치별 위험 수치와 요인 |

### 1.2 화면 구성

1. **추천 화면 (메인)**: 업태와 면적을 고르면 지도가 폐업 위험으로 색칠되고, 위험이 낮은 구역 목록이 나옵니다.
2. **위치 평가 (상세)**: 구역이나 지점을 누르면 위험 수치, 지역 내 순위, 주변 경쟁 점포, 위험 요인을 보여줍니다.

추천은 500m 구역 단위로 합니다. 현재 예측력으로는 건물 단위 비교까지 말하기 어렵기 때문입니다.

### 1.3 고객과 수익 모델

| 고객 | 제공하는 것 | 수익 모델 |
| --- | --- | --- |
| 예비 창업자 | 후보 위치별 입지 리포트 | 리포트 건당 판매 |
| 프랜차이즈 본사 | 출점 후보지 분석 | 월 구독 |
| 은행, 보증기관 | 소상공인 대출 심사 보조 지표 | API 이용료 |

소상공인시장진흥공단이나 서울시의 기존 상권분석 서비스는 상권 단위 통계를 조회하는 방식입니다. 이 서비스는 특정 위치와 조건에 대한 예측 점수, 근거, 더 나은 대안 위치를 제시한다는 점이 다릅니다.

### 1.4 데이터와 이용 조건

| 데이터 | 용도 | 상태 |
| --- | --- | --- |
| 행정안전부 일반음식점 인허가 데이터 (서울, 경기) | 정답과 주변 피처 | 확보 완료 |
| 행정안전부 휴게음식점 인허가 데이터 | 카페 등 업종 확대 | 미확보 |
| 서울시 상권분석서비스 (추정 매출, 유동인구) | 서울 점포의 추가 피처 | 미확보 |
| 지하철역, 버스 정류장, 학교 좌표 | 거리 피처 | 미확보 |

- 인허가 데이터는 이용허락범위에 제한이 없어 상업적 이용이 가능합니다.
- API 일일 호출 제한은 서비스에 영향을 주지 않습니다. 데이터를 한 번 받아 자체 DB에 저장하고, 사용자 요청은 자체 DB로 처리하기 때문입니다.
- 서울 열린데이터광장 데이터와 카카오맵 API는 이용 조건을 따로 확인해야 합니다.

### 1.5 기술 구성

| 구분 | 선택 |
| --- | --- |
| 데이터 처리, 모델 | Python, pandas, scipy(KDTree), LightGBM |
| 백엔드 | FastAPI |
| 프론트엔드 | 카카오맵 JavaScript API, HTML, CSS, JavaScript |
| 좌표 변환 | pyproj (EPSG:5174 → WGS84) |

Streamlit은 사용하지 않습니다.

### 2.2 데이터 정제

| 단계 | 남은 건수 |
| --- | --- |
| 서울 + 경기 원본 | 1,031,310 |
| 다른 시도 주소 제거 | 1,031,277 |
| 인허가일 또는 폐업일 누락 제거 | 1,031,240 |
| 좌표 없는 행, 범위 밖 좌표 제거 | 963,490 |
| 재신고, 명의 변경을 앞 점포에 연결 | 943,501 |
| 30일 이내 폐업(임시 영업) 제거 | 924,666 |
| 학습 대상: 2010년 1월~2023년 11월 개업, 이전 점포 제외 | 345,916 |

인허가 데이터의 폐업에는 실제 폐업이 아닌 경우가 섞여 있어 다음과 같이 처리했습니다.

| 경우 | 판별 기준 | 건수 | 처리 |
| --- | --- | --- | --- |
| 재신고, 명의 변경 | 같은 좌표, 같은 상호로 폐업 30일 전~90일 후에 새 인허가 | 인허가 19,989건 | 하나의 점포로 연결 |
| 이전 | 같은 구(시)에서 같은 상호가 다른 좌표에 전후 90일 내 개업 | 2,562건 | 학습에서 제외 |
| 양도 추정 | 같은 좌표, 같은 면적, 다른 상호로 폐업 7일 전~60일 후에 새 인허가 | 학습 대상 중 29,258건 | 폐업으로 유지, `handover` 컬럼으로 표시 |

양도 추정 건을 빼고 학습해도 AUC가 0.645로 거의 같았습니다.

### 2.3 정답과 피처

정답은 개업 후 3년(1,095일) 안에 폐업하면 1, 아니면 0입니다. 학습 대상의 30.4%가 3년 안에 폐업했습니다.

피처는 모두 해당 점포의 개업일 이전 정보로만 계산했습니다. 주변의 기준은 반경 300m입니다.

| 피처 | 뜻 |
| --- | --- |
| `area` | 점포 면적(㎡) |
| `type` | 업태 (18종) |
| `gu` | 시군구 (서울 25개 구, 경기 31개 시군) |
| `n_all` | 개업 시점에 주변에서 영업 중이던 음식점 수 |
| `n_same` | 그중 같은 업태 점포 수 |
| `same_share` | 주변 음식점 중 같은 업태의 비율 |
| `n_closed_2y` | 개업 전 2년간 주변에서 폐업한 점포 수 |
| `close_rate_2y` | 개업 전 2년간 주변 폐업률 |
| `same_close_rate_2y` | 같은 업태만 본 주변 폐업률 |
| `n_opened_1y` | 개업 전 1년간 주변에 새로 연 점포 수 |
| `spot_prev` | 같은 자리(같은 좌표)에서 먼저 폐업한 점포 수 |
| `spot_fail_rate` | 같은 자리의 이전 점포 중 3년을 못 넘긴 비율 |

### 2.4 모델 결과

2010~2019년 개업 점포(234,950개)로 학습하고, 2020년~2023년 11월 개업 점포(110,966개)로 평가했습니다.

| 모델 | AUC | 위험 상위 10%의 실제 폐업률 | 하위 10% | 전체 평균 |
| --- | --- | --- | --- | --- |
| 로지스틱 회귀 | 0.636 | 57.8% | 19.7% | 34.9% |
| LightGBM | 0.643 | 59.3% | 19.2% | 34.9% |
| LightGBM, 서울만 | 0.653 | 62.1% | 19.0% | 36.5% |
| LightGBM, 경기만 | 0.633 | 56.0% | 18.7% | 33.6% |

- 위험 상위 10%와 하위 10%의 실제 폐업률은 약 3배 차이입니다.
- 변수 기여도는 면적 40.0%, 시군구 22.2%, 업태 7.3%, 같은 자리 이력 7.0%, 주변 2년 폐업률 5.3% 순입니다.
- 면적별 폐업률은 33㎡ 이하 41.2%, 120㎡ 초과 22.4%입니다.
- 예측 확률은 실제보다 낮게 나옵니다(가장 위험한 구간에서 예측 47.2%, 실제 59.3%). 보정이 필요합니다.

### 2.5 데모 지도 페이지

`demo/창업입지지도_데모.html`을 브라우저로 열면 됩니다. 온라인 버전 링크는 6절에 있습니다.

- 업태 18종, 면적 6종, 지역을 고르면 500m 구역 5,595개가 폐업 위험으로 색칠됩니다.
- 위험이 낮은 구역 8곳이 목록과 지도에 번호로 표시됩니다.
- 구역을 누르면 위험 수치, 지역 내 순위, 면적별 위험 비교가 나옵니다.

실제 서비스와 다른 점은 다음과 같습니다.

- 배경 지도가 없고, 격자와 동 이름만 그렸습니다.
- 예측값을 미리 계산해 파일에 넣었습니다. 서버가 없습니다.
- 데모용 모델은 2010~2023년 개업 점포 전체로 다시 학습한 것이고, 이 모델의 성능은 따로 평가하지 않았습니다.

데모 데이터를 만든 스크립트는 `pipeline/참고_구역사전계산_데모용.py`에 있습니다. 3부의 03, 04 스크립트를 만들 때 참고하세요. 파일 경로를 이 묶음에 맞게 바꾼 뒤에는 다시 실행해 보지 않았습니다.

### 2.6 한계

- 예측력은 중간 수준입니다. 폐업에는 맛, 운영 능력, 자금 사정처럼 데이터에 없는 요인이 크게 작용합니다.
- "낫다"는 폐업 위험이 낮다는 뜻입니다. 매출, 임대료, 권리금은 반영하지 않았습니다.
- 좌표가 건물 단위라 같은 건물의 층이나 호실을 구분하지 못합니다.
- 평가 구간이 코로나 시기와 겹칩니다.
- 양도 추정은 추정치이고, 성공적으로 넘긴 경우와 실패해서 넘긴 경우를 구분하지 못합니다.

## 3부. 개발 예정

### 3.1 목표 구조

```
project/
├─ pipeline/          오프라인: 데이터 → 모델, 서빙용 파일
│  ├─ 01_전처리_피처생성.py     (완료)
│  ├─ 02_기준모델.py            (완료)
│  ├─ 03_최종모델_저장.py       (신규)
│  └─ 04_구역_사전계산.py       (신규)
├─ artifacts/         model.txt, stores.parquet, grid.parquet, meta.json
├─ backend/           FastAPI: main.py, features.py, schemas.py
└─ frontend/          index.html, app.js, style.css (카카오맵)
```

### 3.2 1단계: 서빙용 파일 만들기

1. **최종 모델 저장**: 학습 대상 전체로 LightGBM을 학습해 `model.txt`로 저장하고, 업태와 시군구 범주 목록을 `meta.json`에 저장합니다.
2. **점포 테이블 저장**: 정제된 전체 점포(약 92만 건)의 좌표, 업태, 개업일, 폐업일, 시군구를 `stores.parquet`로 저장합니다.
3. **구역 사전 계산**: 500m 구역별, 업태별, 면적별 위험을 계산해 `grid.parquet`로 저장합니다. 구역 네 모서리의 위경도도 함께 넣습니다.
4. **피처 함수 분리**: 좌표, 업태, 면적, 기준일을 받아 피처를 돌려주는 함수를 `features.py` 하나로 만들고, 학습과 서버가 같은 함수를 쓰게 합니다.

### 3.3 2단계: 백엔드 (FastAPI)

서버 시작 시 모델, 점포 테이블, KDTree를 메모리에 올립니다.

| 엔드포인트 | 입력 | 출력 |
| --- | --- | --- |
| `GET /api/meta` | 없음 | 업태, 면적, 지역 목록 |
| `GET /api/grid` | 업태, 면적, 지도 범위 | 범위 안 구역의 좌표와 위험 |
| `GET /api/recommend` | 업태, 면적, 지역 | 위험이 낮은 구역 상위 8곳 |
| `GET /api/predict` | 위도, 경도, 업태, 면적 | 위험 확률, 지역 내 순위, 위험 요인, 주변 통계 |
| `GET /api/nearby` | 위도, 경도, 업태 | 반경 300m 내 영업 중인 점포 목록 |

`/api/predict`만 실시간으로 계산하고, 나머지는 저장된 파일을 조회합니다. 위험 요인은 LightGBM 예측 함수의 `pred_contrib=True` 옵션으로 얻습니다.

### 3.4 3단계: 프론트엔드 (카카오맵)

1. 카카오 개발자 사이트에서 앱을 만들고 JavaScript 키를 발급받아, 플랫폼에 `http://localhost:포트`를 등록합니다. 설정 절차는 공식 문서를 확인하세요.
2. 지도를 띄우고, 지도가 움직일 때마다 `/api/grid`를 불러 화면 범위 안의 구역을 사각형으로 그립니다.
3. 구역이나 지점을 클릭하면 `/api/predict`와 `/api/nearby`를 불러 결과 카드와 주변 점포 마커를 표시합니다.
4. 조건 패널, 추천 목록, 결과 카드는 데모 페이지의 HTML과 CSS를 가져다 씁니다.

### 3.5 개발 순서

| 순서 | 목표 | 완료 기준 |
| --- | --- | --- |
| 1 | 서빙용 파일 생성 | `artifacts/`에 파일 4개 생성 |
| 2 | `/api/predict` | 브라우저 주소창에 좌표를 넣으면 확률이 나옴 |
| 3 | 지도 + 클릭 예측 | 지도를 클릭하면 결과 카드가 뜸 |
| 4 | 히트맵 + 추천 목록 | 조건을 바꾸면 색과 목록이 바뀜 |
| 5 | 주변 점포 마커, 위험 요인 설명 | 카드에 이유가 표시됨 |
| 6 | 확률 보정, 예외 처리 | 서울·경기 밖을 클릭하면 안내 문구가 나옴 |

2번까지 한 명이 하는 동안 다른 한 명이 가짜 응답으로 3번 화면을 먼저 만들면 병렬로 진행할 수 있습니다.

### 3.6 미리 정해 둘 것

- **임의 지점의 시군구**: 모델이 시군구를 입력으로 씁니다. 가장 가까운 점포의 시군구를 쓰거나, 카카오의 좌표→행정구역 변환 API를 씁니다.
- **음식점이 없는 곳**: 주변 300m에 점포가 거의 없는 지점은 예측을 믿기 어렵습니다. 주변 음식점이 5곳 미만이면 예측하지 않는 식의 규칙을 둡니다.
- **키 관리**: 카카오 JavaScript 키는 도메인 제한을 걸고, 공공데이터 인증키는 `.env`에 두고 깃에 올리지 않습니다.
- **CORS**: 프론트엔드를 FastAPI가 정적 파일로 함께 서빙하면 CORS 설정이 필요 없습니다.
- **역할 분담**: 데이터와 모델, 백엔드, 프론트엔드, 발표 자료.

## 4. 실행 방법

원본 CSV 두 개(`식품_일반음식점_서울특별시.csv`, `식품_일반음식점_경기도.csv`)를 `pipeline/` 폴더에 넣고 실행합니다.

```
pip install pandas numpy scipy pyproj lightgbm scikit-learn
cd pipeline
python 01_전처리_피처생성.py     # 서울경기_일반음식점_학습데이터.csv 생성
python 02_기준모델.py            # 성능 수치 출력
```

`02_기준모델.py`는 이 문서의 수치를 낸 그대로입니다. `01_전처리_피처생성.py`는 같은 코드로 결과를 만든 뒤 중간 저장 한 줄을 지웠고, 그 최종본은 다시 실행해 보지 않았습니다.
