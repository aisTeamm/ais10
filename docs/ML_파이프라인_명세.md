# 창업입지 ML 파이프라인 명세

작성일: 2026-11-16
온라인 문서: https://claude.ai/artifact/6oRzh2Xt3KBikwcLqGtk11

## 1. 개요

이 파이프라인은 일반음식점의 업태, 면적, 위치를 입력받아 **개업 후 3년 안에 폐업할 확률(0~1)**을 출력합니다. 학습은 오프라인 스크립트 01, 02로 하고, 서비스는 저장된 모델과 점포 테이블로 추론합니다. 이 문서는 서비스 개발자가 학습과 같은 방식으로 피처를 계산하고 모델을 호출할 수 있도록 입출력과 규칙을 정리합니다.

| 항목 | 내용 |
| --- | --- |
| 예측 문제 | 이진 분류: 개업 후 1,095일 안에 폐업하면 1 |
| 모델 출력 | 폐업 확률 0~1 (`predict_proba(X)[:, 1]`) |
| 지역, 업종 | 서울특별시, 경기도의 일반음식점 |
| 데이터 | 행정안전부 일반음식점 인허가 데이터 (서울 541,336건, 경기 489,974건) |
| 모델 | LightGBM 이진 분류 (기준선: 로지스틱 회귀) |
| 현재 성능 | AUC 0.643, 위험 상위 10% 실제 폐업률 59.3% vs 하위 10% 19.2% |
| 코드 | `pipeline/01_전처리_피처생성.py`, `pipeline/02_기준모델.py`, `pipeline/참고_구역사전계산_데모용.py` |

```
[오프라인 학습: pipeline/]
원본 인허가 CSV ──▶ 01 전처리·피처 ──▶ 02 기준모델 ──▶ 03·04 서빙 파일
(서울·경기 103만 건)  (정답 + 피처 12개)   (시간 분할 평가)   (model·stores·grid)
                        ┆ 같은 피처 함수                         │ 서버 시작 시 로드
                        ▼                                        ▼
[서빙: FastAPI]
사용자 입력 ──────▶ features.py ──────▶ LightGBM 예측 ──▶ 폐업 확률 0~1
(업태·면적·위경도)  (시군구 + 주변 피처)  (predict_proba)    (지도·추천·위험 요인)
```

오프라인에서 만든 모델과 점포 테이블을 서버가 시작할 때 올리고, 피처는 학습과 같은 함수로 계산합니다.

## 2. 데이터와 정제 규칙

원본 인허가 데이터 1,031,310건을 정제하면 점포 924,666개가 남고, 이 점포 테이블이 학습과 추론 양쪽의 이웃 검색 대상입니다. 서비스의 `stores.parquet`는 이 규칙을 그대로 거친 결과여야 합니다.

### 2.1 원본 컬럼

| 원본 컬럼 | 내부 이름 | 용도 |
| --- | --- | --- |
| 관리번호 | `id` | 점포 식별 |
| 인허가일자 | `open` | 개업일, 시점 기준 |
| 영업상태명 | `status` | 폐업 여부 |
| 폐업일자 | `close` | 정답, 영업 중 판단 |
| 소재지면적 | `area` | 피처 (0 이하는 결측) |
| 사업장명 | `name` → `nm` | 재신고, 이전, 양도 판별 (공백과 괄호 제거) |
| 업태구분명 | `type` | 피처 (1,000건 미만은 '기타') |
| 도로명주소, 지번주소 | `addr` | 시도 검증, 시군구 `gu` 추출 |
| 좌표정보(X), (Y) | `x`, `y` | EPSG:5174(미터). 거리 계산은 이 좌표, 표시는 WGS84 변환값 |

### 2.2 정제 단계

1. 다른 시도 주소 제거 → 1,031,277건
2. 인허가일 누락, 폐업인데 폐업일 누락 제거 → 1,031,240건
3. 좌표 없음, 범위 밖 좌표(위도 36.85~38.35, 경도 126.3~127.9 밖) 제거 → 963,490건
4. 재신고, 명의 변경을 하나의 점포로 연결 → 943,501개
5. 30일 이내 폐업(임시 영업) 제거 → 924,666개

### 2.3 폐업이 아닌 폐업 처리

| 경우 | 판별 기준 | 처리 |
| --- | --- | --- |
| 재신고, 명의 변경 | 같은 자리(좌표 키 `k`), 같은 상호로 폐업 30일 전~90일 후 새 인허가 | 한 점포로 연결. 개업일은 첫 인허가, 폐업일과 업태는 마지막 인허가 |
| 임시 영업 | 개업 후 30일 이내 폐업 | 제거 |
| 이전 | 같은 시군구, 같은 상호(2글자 이상, 출현 10회 이하)가 다른 자리에 ±90일 안에 개업 | `moved=1`, 학습 대상에서 제외 (이웃 계산에는 포함) |
| 양도 추정 | 같은 자리, 같은 면적, 다른 상호로 폐업 7일 전~60일 후 새 인허가 | 폐업으로 유지, `handover=1` 표시 |

양도 추정 건을 빼고 학습해도 AUC는 0.645로 거의 같아서, 기본 설정은 포함입니다.

## 3. 정답과 학습 대상

정답 `closed_3y`는 개업 후 1,095일(3년) 안에 폐업하면 1, 아니면 0입니다. 학습 대상 345,916개 중 30.4%가 1입니다.

```
closed_3y = 1  if (close - open) <= 1095일  else 0
```

| 규칙 | 내용 |
| --- | --- |
| 폐업일 없음 | 아직 영업 중(휴업 포함)으로 보고 0 |
| 데이터 기준일 `SNAP` | 서울, 경기 각각의 최신 인허가일 중 이른 날 |
| 학습 대상 개업일 | 2010-01-01 ~ (SNAP − 1,095일). 현재 2023년 11월까지 |
| 제외 | 개업 3년이 안 지난 점포(정답을 아직 모름), 이전 점포(`moved=1`) |
| 포함 | 양도 추정 점포(`handover=1`)는 폐업으로 포함 |

학습 대상에서 빠진 점포도 이웃으로는 계속 씁니다. 학습 대상은 "정답을 아는 점포"이고, 이웃 후보는 "정제된 점포 전체"입니다.

## 4. 입력 피처

모델 입력은 수치 10개와 범주 2개, 총 12개입니다. 사용자가 직접 주는 것은 업태, 면적, 위치 3가지뿐이고, 나머지는 서버가 점포 테이블에서 계산합니다. 열 순서는 아래 표 순서(`num + cat`)를 지켜야 합니다.

### 4.1 피처 목록

기호: t = 기준 시점(학습은 개업일, 추론은 오늘 또는 SNAP), 주변 = EPSG:5174 좌표 기준 반경 300m, 선행 = 개업일 < t인 점포.

| # | 피처 | 타입 | 얻는 곳 | 계산 |
| --- | --- | --- | --- | --- |
| 1 | `area` | float (㎡) | 사용자 입력 | 점포 면적. 0 이하는 NaN |
| 2 | `n_all` | int | 계산 | 주변의 선행 점포 중 t에 영업 중(폐업일 ≥ t 또는 없음) |
| 3 | `n_same` | int | 계산 | 2 중 같은 업태 |
| 4 | `n_closed_2y` | int | 계산 | 주변의 선행 점포 중 t−730일 ≤ 폐업일 < t |
| 5 | `n_opened_1y` | int | 계산 | 주변에서 t−365일 ≤ 개업일 < t (이후 폐업 여부 무관) |
| 6 | `close_rate_2y` | float | 계산 | n_closed_2y / (n_all + n_closed_2y) |
| 7 | `same_close_rate_2y` | float | 계산 | n_same_closed_2y / (n_same + n_same_closed_2y) |
| 8 | `same_share` | float | 계산 | n_same / n_all |
| 9 | `spot_prev` | int | 계산 | 같은 자리(x, y 차이 합 < 1m)에서 t 전에 폐업한 선행 점포 수 |
| 10 | `spot_fail_rate` | float | 계산 | spot_prev 중 수명 ≤ 1,095일인 비율 |
| 11 | `type` | category (18종) | 사용자 입력 | 업태. 학습 때의 범주 목록을 그대로 사용 |
| 12 | `gu` | category (56개) | 위치로 판단 | "서울 강남구", "경기 수원시" 형식. 시도 앞 2글자 + 주소의 두 번째 단어 |

- 비율 피처(6~8, 10)는 분모가 0이면 NaN입니다. 0으로 채우지 마세요. LightGBM은 NaN을 그대로 처리합니다.
- 학습 CSV의 `n_same_closed_2y`, `spot_prev_closed_3y`는 비율 계산에만 쓰는 중간값이고 모델 입력이 아닙니다.
- 로지스틱 회귀는 개수 피처 6개에 log1p, 중앙값 대치, 표준화, 범주는 원핫 인코딩을 씁니다. 서비스 모델인 LightGBM은 변환이 필요 없습니다.

### 4.2 누수 방지 규칙

1. 모든 피처는 기준 시점 t 이전 정보로만 계산합니다. 나보다 늦게 연 점포나 t 이후의 폐업은 보지 않습니다.
2. 추론에서는 t = 기준일이므로 "지금 영업 중"인 점포가 n_all이 됩니다. 학습과 같은 함수에 t만 바꿔 넣어야 합니다.
3. 거리는 위경도가 아니라 EPSG:5174 미터 좌표로 계산합니다. 사용자가 준 위경도는 먼저 5174로 변환합니다.

## 5. 출력

모델은 0/1이 아니라 **3년 내 폐업 확률(0~1)**을 돌려줍니다. 서비스는 이 확률로 지도를 색칠하고 순위를 매깁니다.

```python
p = model.predict_proba(X)[:, 1]   # 예: 0.31 = 3년 내 폐업 확률 31%
```

| 항목 | 규칙 |
| --- | --- |
| 기본 출력 | `predict_proba`의 확률. `predict()`(0.5 기준 0/1)는 쓰지 않음 |
| `predict()`를 쓰지 않는 이유 | 예측 확률이 0.5를 넘는 경우가 드물어 거의 모두 0이 됨 |
| 등급이 필요할 때 | 학습 대상 예측값의 분위수로 자름. 예: 상위 10% 고위험, 하위 10% 저위험 |
| 여러 건 입력 | 행마다 확률 1개 |
| 지역 내 순위 | 같은 업태, 면적 조건에서 같은 시군구 구역들의 확률과 비교 |
| 위험 요인 | LightGBM `predict(X, pred_contrib=True)`로 피처별 기여도(로그오즈 단위) |

### 5.1 확률 보정 (미완료)

현재 확률은 실제보다 낮게 나옵니다. 가장 위험한 구간에서 예측 평균은 47.2%인데 실제는 59.3%입니다. 확률을 숫자로 보여주기 전에 평가 구간으로 Isotonic 또는 Platt 보정기를 학습해 모델 뒤에 붙입니다. 순위와 색칠은 순서만 쓰므로 보정 전에도 쓸 수 있습니다.

## 6. 학습과 평가

서비스 모델은 LightGBM입니다. 시간 기준 분할에서 로지스틱 회귀보다 AUC가 0.007 높고, 상위 10% 폐업률도 1.5%p 더 잘 가려냅니다.

### 6.1 데이터 분할

| 구간 | 개업일 | 건수 | 용도 |
| --- | --- | --- | --- |
| 학습 | 2010-01 ~ 2017-12 | | 조기 종료용 학습 |
| 검증 | 2018-01 ~ 2019-12 | | 조기 종료로 트리 수 결정 |
| 학습 전체 | 2010-01 ~ 2019-12 | 234,950 | 정해진 트리 수로 다시 학습 |
| 평가 | 2020-01 ~ 2023-11 | 110,966 | 성능 보고 |

무작위 분할을 쓰지 않습니다. 과거로 학습해 미래를 예측하는 실제 사용 상황을 흉내 내기 위함입니다.

### 6.2 하이퍼파라미터 (LightGBM)

```python
P = dict(learning_rate=0.03, num_leaves=31, min_child_samples=100,
         subsample=0.8, subsample_freq=1, colsample_bytree=0.8,
         cat_smooth=50, verbose=-1)
# n_estimators: 조기 종료(patience 100, AUC) 결과. 데모용 최종 모델은 230
```

`type`, `gu`는 pandas `Categorical`로 넣고, 범주 목록은 학습 데이터의 정렬된 고유값입니다. 추론 때도 같은 목록을 써야 코드가 일치합니다.

### 6.3 평가 지표와 결과

지표는 AUC와, 예측 위험 상위 10% · 하위 10%의 실제 폐업률입니다.

| 모델 | AUC | 상위 10% 폐업률 | 하위 10% | 전체 평균 |
| --- | --- | --- | --- | --- |
| 로지스틱 회귀 | 0.636 | 57.8% | 19.7% | 34.9% |
| LightGBM | 0.643 | 59.3% | 19.2% | 34.9% |
| LightGBM, 서울만 | 0.653 | 62.1% | 19.0% | 36.5% |
| LightGBM, 경기만 | 0.633 | 56.0% | 18.7% | 33.6% |

변수 기여도(gain)는 면적 40.0%, 시군구 22.2%, 업태 7.3%, 같은 자리 이력 7.0%, 주변 2년 폐업률 5.3% 순입니다. 평가 구간이 코로나 시기와 겹칩니다.

## 7. 추론(서빙)

추론은 두 가지입니다. 지점 하나를 누르면 실시간으로 계산하고(`/api/predict`), 지도 색칠과 추천은 미리 계산한 구역 값을 조회합니다. 어느 쪽이든 모델을 다시 학습하지 않습니다.

### 7.1 실시간 예측 흐름

1. 입력 받기: 위도, 경도, 업태, 면적(㎡)
2. 검증: 업태가 18종 목록에 있는지, 좌표가 서울·경기 범위 안인지 확인
3. 좌표 변환: WGS84 → EPSG:5174 (pyproj, `always_xy=True`)
4. 시군구 결정: 가장 가까운 점포의 `gu` 또는 카카오 좌표→행정구역 API (미결, 9절)
5. 이웃 검색: 서버 시작 시 올린 KDTree로 반경 300m 점포 조회
6. 피처 계산: `features.py`의 공용 함수에 t = 데이터 기준일을 넣어 10개 수치 피처 계산
7. 예측: 12개 피처를 학습 때와 같은 열 순서, 같은 범주 목록으로 만들어 `predict_proba`
8. 설명: `pred_contrib=True`로 위험 요인 상위 피처 추출

### 7.2 구역 사전 계산

| 항목 | 값 |
| --- | --- |
| 구역 | EPSG:5174 좌표를 500m로 나눈 격자 (`gx = x // 500`, `gy = y // 500`) |
| 대상 구역 | 기준일에 영업 중인 점포가 5곳 이상. 현재 5,595개 |
| 후보 지점 | 구역 안 영업 중 점포가 있는 건물, 무작위 최대 12곳 (`random_state=0`) |
| 조합 | 업태 18종 × 면적 6종(20, 33, 50, 66, 100, 165㎡) |
| 구역 위험 | 후보 지점 확률의 중앙값 |
| 데모 저장 형식 | 확률 × 200을 uint8로, base64 인코딩 (`demo_data.json`) |
| 서비스 저장 형식 | `grid.parquet`: 구역 아이디, 네 모서리 위경도, 업태, 면적, 위험 |

### 7.3 API 입출력

| 엔드포인트 | 입력 | 출력 | 계산 |

| `GET /api/nearby` | 위도, 경도, 업태 | 반경 300m 안 영업 중 점포 목록 | KDTree 조회 |

## 8. 데이터 추가와 재학습

새 점포를 예측하는 것은 재학습이 필요 없고, 학습 데이터를 늘리거나 피처를 바꾸면 01부터 다시 실행합니다. 어느 경우든 출력은 확률입니다.

| 상황 | 재학습 | 해야 할 일 |
| --- | --- | --- |
| 새 위치·조건으로 예측 (추론) | 필요 없음 | 저장된 모델에 피처를 계산해 넣기만 함 |
| 최신 인허가 데이터로 갱신 | 필요 | 원본 CSV 교체 → 01 → 02 → 03 → 04. SNAP이 늦어지면 학습 대상도 자동으로 늘어남 |
| 업종 추가 (휴게음식점 등) | 필요 | 원본 CSV 추가, `FILES`와 업태 목록 확장 → 01부터 다시 실행 |
| 새 피처 추가 (역 거리, 프랜차이즈 등) | 필요 | 01과 `features.py`에 계산 추가, 02의 `num`/`cat` 갱신, AUC 비교 후 채택 |

- 학습 CSV에 행만 덧붙이면 안 됩니다. 정답과 주변 피처는 점포끼리의 관계로 계산되기 때문에, 새 점포가 들어오면 기존 점포의 피처도 바뀝니다.
- 새 피처도 기준 시점 t 이전 정보만 써야 합니다 (4.2절).
- 재학습 뒤에는 `model.txt`, `meta.json`, `stores.parquet`, `grid.parquet`를 한 번에 교체합니다. 하나만 바꾸면 범주 목록이나 피처가 어긋납니다.

## 9. 서빙 산출물과 미결 사항

서비스는 `artifacts/`의 파일 4개만 읽습니다. 두 스크립트 03, 04가 아직 없으며, 데모용 스크립트를 참고해 만듭니다.

| 파일 | 내용 | 만드는 곳 |
| --- | --- | --- |
| `model.txt` | LightGBM 모델 (학습 대상 전체로 학습) | 03 |
| `meta.json` | 피처 열 순서, `type`·`gu` 범주 목록, 면적 목록, SNAP, 반경, 모델 버전 | 03 |
| `stores.parquet` | 정제된 점포 전체(약 92만): x, y, lat, lon, type, gu, open, close | 03 |
| `grid.parquet` | 500m 구역 × 업태 × 면적별 위험, 네 모서리 위경도 | 04 |

### 주의사항

- **피처 함수는 하나만 둡니다.** 현재 01과 데모 스크립트가 같은 로직을 따로 구현하고 있습니다. `features.py`로 합쳐 01, 04, 서버가 모두 호출하게 합니다.
- **범주 목록을 고정합니다.** 추론 때 `pd.Categorical(..., categories=meta['types'])`처럼 학습 때의 목록을 써야 합니다. 요청 데이터로 목록을 만들면 코드가 바뀌어 예측이 조용히 틀립니다.
- **데모 모델은 평가되지 않았습니다.** 트리 230개, 전체 데이터 학습이며 별도 검증이 없습니다.
- **확률 보정 전에는 확률 숫자를 그대로 보여주지 않습니다** (5.1절).
